Step 01

Locate the “Add file” dropdown

Inside your repository overview, look directly above the file list on the right-hand side. GitHub provides a quiet menu for creating files on the fly without running any terminal commands.

Pro tip: You don't need Git installed on your computer yet. GitHub allows you to author files entirely in the cloud.

Step 02

Name your fileREADME.md

The README file is the welcome mat of any software repository. GitHub automatically recognizes this filename and renders its rich text on your project's main repository homepage for anyone who visits.

help

Why .md? It stands for Markdown, a plain-text syntax that makes formatting bold text, bulleted lists, and hyperlinks completely effortless.

Step 03

Write a clear commit message

Scroll to the bottom of the page to find the “Commit changes” panel. A commit message is a concise historical memorandum explaining what you altered and why.

bookmark

Best practice: Keep your commit title under 50 characters, phrased in the present tense like “Initial commit” or “Add project description”.

Vocabulary

Words you'll meet

Core version control concepts translated into calm, human metaphors.

folder_managed

Repository

A dedicated digital container where all project files, history, and revisions live harmoniously together.

Think of it like

“A smart project vault that remembers every single revision ever saved.”

alt_route

Branch

An isolated parallel timeline where you can experiment freely without risking the stability of production code.

Think of it like

“A draft photocopy you scribble on before touching the master archival document.”

check_circle

Commit

A permanent snapshot of your files at a specific moment in time, accompanied by an explanatory author note.

Think of it like

“A saved checkpoint in an adventure game with a stamped timestamp and notes.”

Mental Model

Visual Concept: What is a branch?

main feature
1. Branching off

You create a clean workspace safely detached from your live code.

2. Committing changes

Each commit creates an incremental, recoverable milestone of work.

3. Merging back

When polished, your changes combine gracefully back into the master timeline.
